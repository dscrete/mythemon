# Aeglet art specification

Status: exploration

This file is the persistent visual handoff for Aeglet. Keep it compact and
update it when the user approves a design decision or a PixelLab setting proves
useful for consistent derivatives.

## Core concept

- Small, unevolved Psychic-type Mythmon.
- Myth-themed / mystical, fox-like, cute but elegant.
- Must remain practical as a base form for a later evolution.
- Large upright ears are a defining silhouette feature.
- Forehead ornament should read as a small mystical gem, crest, or crown-like
  feature rather than a large horn.
- Tail should remain fluffy and curled/crescent-like in spirit.
- Magical accents should be restrained rather than visually noisy.

## Visual target

- Polished Gen 2-inspired Pokemon sprite readability.
- True-color artwork is allowed where Gen1Recomp supports it.
- Strong silhouette at native game size.
- Deliberate pixel clusters; no blurry resampling or painterly anti-aliasing.
- More refined than Gen 1, but not modern/high-resolution illustration detail.
- The design should remain simple enough to animate, turn around, and reduce to
  overworld and menu-icon scale without losing identity.

## Current palette direction

The existing shipped artwork uses tan/brown/cream with restrained purple and a
small gold accent. This is useful direction, but the palette is not locked while
Aeglet is being redesigned through PixelLab.

## Locked features

None yet. The current front sprite is not authoritative; Aeglet is intentionally
being redesigned with PixelLab before the production asset family is derived.

## Current shipped runtime assets

These remain in production until replacements are explicitly approved:

- `assets/aeglet_front.png` — 56x56 transparent PNG
- `assets/aeglet_back.png` — 32x32 transparent PNG
- `assets/aeglet_icon.png` — 16x32 transparent two-frame PNG

Do not overwrite them during exploration.

## PixelLab exploration goals

1. Establish a stronger master Aeglet design, starting with front-sprite
   candidates.
2. Prefer a small batch of coherent alternatives over a large random batch.
3. Once a candidate is approved, record the approved reference/image identifier,
   prompt/settings, palette decisions, silhouette notes, and defining markings
   below.
4. Use that locked master to derive the back view.
5. Test a small animation batch for frame-to-frame identity consistency.
6. Only then expand into overworld directions/walk cycles, menu icons, and shiny
   derivatives.
